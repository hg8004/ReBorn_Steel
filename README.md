# 리본스틸(ReBorn Steel) 스크랩 배합 AI 에이전트

인공지능재료공학 수업 과제로 만든 프로젝트다. 가상의 전기로 제강사 '리본스틸'에서 철스크랩을 몇 톤씩 섞을지 정한다. 목표는 두 가지다. 원가는 낮추고, Cu·Sn 규격은 지킨다.

> 회사, 설비, 시세, 성분, 조업 이력은 전부 AI가 만든 가상 데이터다. 실제 기업이나 공개 데이터와는 관계없다.

사이트: https://hg8004.github.io/ReBorn_Steel/

결과물은 두 갈래다.

- **파이썬 에이전트**(`src/`): 합성 데이터를 만들고, 도구 6개로 하루 24 heat 배합 지시서를 쓰고, 숨은 정답으로 v1·v2·v3을 채점한다. 아래 평가 결과가 여기서 나왔다.
- **사내포털**(`docs/`): 같은 계산을 브라우저로 옮긴 사이트다. 핵심 화면인 'AI 배합 설계'에서는 조건을 직접 넣으면 Claude가 도구를 골라 쓰면서 배합을 풀고, 그 과정이 화면에 그대로 남는다.

## 실행 방법

사이트만 써 볼 거라면 설치할 것이 없다. 위 주소로 들어가거나 `docs\index.html`을 브라우저로 열면 된다.

파이썬 쪽을 다시 돌릴 때는 아래 순서다.

```powershell
pip install -r requirements.txt

# 1) 합성 데이터 만들기 (시드 고정, 몇 초 걸림)
python src/generate_data.py

# 2) 에이전트로 하루치(24 heat) 배합 지시서 만들기
python src/agent.py --date 2026-09-25

# 3) 숙련자 배합과 v1·v2·v3 비교 평가 (그래프와 사내포털 데이터도 같이 갱신)
python src/evaluate.py

# 4) 사내포털 열기
start docs\index.html
```

윈도우 터미널에서 한글이 깨지면 먼저 `$env:PYTHONIOENCODING='utf-8'`를 입력한다. 사내포털용 회사 데이터만 다시 만들 때는 `python src/export_intranet.py`를 쓴다.

### Claude API 키

Claude는 두 곳에서 쓴다. 키는 어디에도 코드로 적지 않는다.

파이썬 에이전트는 환경변수로 키를 받는다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
```

키가 있으면 `agent.py`에서 Claude(`claude-opus-5-5`)가 도구를 직접 골라 쓰고, 검수 메모 판정(도구 2)과 지시서 근거 문장(도구 6)도 맡는다. 키가 없으면 같은 도구를 정해진 순서로 부르는 `pipeline.run_full`이 대신 돈다. 이때 검수 메모는 키워드 규칙으로, 근거 문장은 고정 템플릿으로 처리한다. 키가 있어도 `python src/evaluate.py --no-llm`으로 LLM 없이 평가할 수 있다. LLM 응답은 `outputs/cache/`에 저장해 다시 쓰기 때문에, 다시 돌려도 결과가 같고 비용도 거의 들지 않는다. 안전 분류기가 요청을 거절하면 서버가 다른 모델로 넘기도록 server-side fallback도 켜 두었다(`src/llm.py`).

사이트의 'AI 배합 설계'는 화면에서 각자 키를 넣는다. TimelyGPT 연동 키(`tgpt_sk_`)를 넣으면 TimelyGPT를 거쳐 Claude나 GPT를 쓰고, 비용은 타임리 스페이스 크레딧에서 나간다. Claude 키(`sk-ant-`)가 있으면 Anthropic에 바로 연결한다. 자세한 내용은 아래 [AI 배합 설계](#ai-배합-설계)에 있다.

  mail.html                  사내 메일함 (오늘 할 일이 메일로 온다)
  ops.html, yard.html        오늘의 조업 현황, 스크랩 야드·검수
  company.html               회사·공지·조직·설비
  report.html                AI 배합 도입 보고서 (과제 요구사항 ①~⑤와 검증 차트)
  assets/engine.js           브라우저 계산 엔진 (선형계획, 모의 조업, 안전여유 조정)

## AI 배합 설계

사이트의 핵심 화면이다(`docs/agent.html`). 정해진 답이 없다. 조건을 넣고 실행하면 그때 풀린다.

**넣는 조건.** 스크랩 등급마다 단가, 재고, 실수율, 부피밀도, Cu·Sn 평균과 편차를 넣는다. 등급은 추가하거나 지울 수 있다(최대 15개). 강종마다 Cu·Sn 상한, heat 수, heat당 출강량을 넣고, 목표 이탈 확률(1~5%)과 버킷 용적, 검수 메모를 넣는다. 처음에는 평가 기간의 한 날짜 조건이 채워져 있고, 다른 날짜를 불러와 고쳐도 된다. 값이 이상하면(단가 0, 실수율 1 초과 등) 실행 버튼이 잠기고 이유가 뜬다.

**AI 연결.** 키 앞부분을 보고 연결 방법을 고른다.

| 키 | 연결 | 쓸 수 있는 모델 |
|---|---|---|
| TimelyGPT 연동 키 `tgpt_sk_…` | TimelyGPT Direct API (`hello.timelyai.io/api/v2/chat/direct`). Claude 모델은 Anthropic 형식(`/anthropic/v1/messages`), GPT 모델은 OpenAI 형식(`/openai/v1/chat/completions`)으로 보낸다 | 스페이스·그룹에서 켜 둔 모델. 화면의 '쓸 수 있는 모델 불러오기'로 확인한다 |
| Claude 키 `sk-ant-…` | Anthropic 공식 SDK | Claude Opus 5.5, Sonnet 5.5, Haiku 5.5 |

**AI와 계산기의 역할.** AI 에이전트는 아래 도구 6개를 스스로 골라 부른다. 계산은 모두 브라우저의 `engine.js`와 `analysis.js`가 하고, AI는 도구가 돌려준 숫자만 쓴다. Claude를 고르든 GPT를 고르든 도구와 역할은 같다.

| 도구 | 하는 일 | AI가 정하는 것 |
|---|---|---|
| `get_conditions` | 입력 조건과 첫 안전여유 제안값을 돌려준다 | 없음 |
| `analyze_history` | 회사 기록을 주제별로 분석한다 (아래 표) | 어떤 기록을 볼지 |
| `optimize_blend` | 모든 heat의 원가 최소 배합을 선형계획법으로 한 번에 푼다. 배합을 묶고 있는 제약(어느 원소 상한, 어느 등급 재고)도 알려 준다 | 강종별 안전여유, 검수 메모마다 제외·5% 제한·영향 없음 판정과 이유 |
| `simulate_blend` | 최근 배합으로 모의 조업 1,000회를 돌려 heat별 이탈 확률과 여유 조정 제안을 준다 | 다시 계산할지, 여유를 얼마나 키울지 |
| `sensitivity` | 변인 하나(단가, 등급 Cu 함량, 재고, 강종 Cu 상한, 목표 이탈 확률)만 바꿔 다시 풀고 원가·배합·이탈 확률 변화를 잰다 | 어떤 변인을 얼마나 바꿔 볼지 |
| `write_report` | 배합 결정 통지서를 쓴다 | 요약, 이렇게 정한 이유, 변인 해석, 위험과 대응, 제안 |

`analyze_history`가 보는 기록은 이렇다. 모두 회사가 가진 CSV에서 내보낸 것이고 숨은 정답은 쓰지 않는다.

| 주제 | 내용 |
|---|---|
| `grade_contribution` | 조업 이력 500 heat로 역추정한 등급별 Cu·Sn, 공칭값과의 차이, 과거 배합에서 Cu가 어느 등급에서 왔는지, 회귀 적합도 |
| `spec_margin` | 강종별 과거 출강 성분이 상한에 얼마나 가까웠는지, 과거 평균 배합을 오늘 단가로 사면 톤당 얼마인지 |
| `price_trend` | 최근 30일 시세 변동, 등급 간 Cu와 단가의 관계(Cu 0.1%p당 단가 차이) |
| `inventory` | 재고가 평소·과거 하루 사용량 대비 넉넉한지, 오늘 배합이 재고를 다 썼는지 |
| `notes_history` | 지난 검수 메모, 성분 회귀에서 잔차가 컸던 날과 그날의 메모, 키워드가 있지만 '제거 완료'처럼 해결 문구가 붙은 메모 |
| `power` | 등급별 톤당 전력량 (원가에는 넣지 않고 참고만) |

**배합 결정 통지서.** 마지막에 AI가 제강팀장에게 보내는 통지서를 쓴다. 문장(요약, 이유, 변인 해석, 위험, 제안)은 AI가 쓰고, 숫자 표는 화면이 도구 결과로 직접 채운다. 표에는 강종별 배합과 묶는 제약, 등급별 사용량과 재고, 변인 영향 막대 그래프, 회차별 검증 과정이 들어간다. 그래서 문장 속 판단과 표의 숫자를 나란히 대조할 수 있다. 인쇄하거나 PDF로 저장할 수 있다. '팀장님께 통지'를 누르면 사내 메일함에 결재 메일로 들어가고, 메일의 링크로 통지서 전문을 다시 연다. 통지한 배합은 그날의 '오늘의 조업 현황', 홈, 스크랩 야드에도 바로 반영된다(통지서와 함께 heat별 배합을 이 브라우저에 저장). 조업 현황에서 '자동 초안 보기'를 누르면 배합 에이전트의 자동 초안과 비교할 수 있다. AI가 통지서를 쓰지 않고 끝나면, 숫자로 채운 규칙 기반 통지서가 대신 붙는다. 통지서와 메일에는 어느 모델이 썼는지 남는다.

**화면에 남는 것.** AI의 생각 요약(모델이 보여 주는 경우), 도구 호출과 그 입력값(안전여유, 메모 판정), 도구 결과가 순서대로 쌓인다. 끝나면 톤당 원가, 숙련자 배합 대비 절감(등급이 기본 8종 그대로일 때만), 최대 이탈 확률, 강종별 배합 비율, heat별 배합 지시가 나온다. 토큰 사용량도 같이 보인다. Claude 키로 Opus 5.5를 쓸 때만 추정 비용(100만 토큰당 입력 $4·출력 $20)을 달러로 보여 주고, TimelyGPT는 크레딧에서 차감된다고만 표시한다.

**발표 모드.** 끝난 실행은 이 브라우저에 최근 8건 저장된다. '발표 모드'를 누르면 글자가 커지고, 다음·이전 버튼이나 ←/→ 키로 한 단계씩 넘기며 보여 줄 수 있다. 발표장 인터넷이 불안하면 미리 풀어 둔 실행을 불러와 쓰면 된다.

**AI 없이 계산.** 키가 없으면 같은 도구를 키워드 규칙(메모에 '전선', '모터' 같은 단어가 있으면 제외)과 정해진 여유 조정 규칙으로 돌린다. 기록 분석과 변인 분석도 정해진 순서로 부르고, 통지서는 정해진 틀에 숫자를 채워 쓴다. 같은 조건에서 둘을 돌려 보면 AI가 무엇을 다르게 판단했는지 비교할 수 있다. 9/29처럼 '선별 후 전량 제거 완료' 메모가 있는 날이 좋은 예다. 키워드 규칙은 '전선'만 보고 그 등급을 뺀다.

**구현 메모.**

- 서버는 없다. 브라우저가 AI 서버를 바로 부른다.
- TimelyGPT 서버는 브라우저 호출(CORS)에 `Content-Type`과 `Authorization` 헤더만 허용한다(2026-11 확인). 그래서 TimelyGPT 쪽은 SDK 대신 `fetch`로 부르고, 키는 `Authorization: Bearer`로 보낸다. 서버가 받지 않는 옵션 때문에 400이 나면 `output_config`, 생각 요약 표시, strict 순서로 하나씩 빼고 다시 보낸다.
- Claude 키로 연결할 때는 공식 SDK `@anthropic-ai/sdk`(1.6.0)를 jsdelivr에서 불러온다(`dangerouslyAllowBrowser`).
- 오류는 TimelyGPT 문서의 상태 코드 표대로 안내한다. 401은 키, 402는 크레딧·한도, 403은 꺼진 모델이나 IP 제한, 404는 없는 모델이다.
- 도구 루프는 직접 짰다. 응답을 그대로 대화에 다시 붙이고, 도구 결과는 한 메시지에 모아 돌려준다. 한 번에 여러 도구를 같이 부를 수 있다. 호출은 최대 30번, 최적화는 최대 8번까지다.
- Claude 모델은 adaptive thinking(요약 표시)을 쓰고, 도구 입력은 strict 스키마로 묶었다. 메모 ID와 강종 이름은 그때 입력에 맞춰 enum으로 만든다. Claude 키로 직접 연결할 때는 server-side fallback도 켠다. GPT 모델에는 같은 스키마를 OpenAI 함수 형식(`function.parameters`)으로 바꿔 보낸다.
- 키는 브라우저에서 AI 서버(TimelyGPT 또는 Anthropic)로만 간다. 코드와 저장소에는 넣지 않고, '기억'을 켜면 그 창(sessionStorage)에만 둔다.
- 성분 추정(파이썬 도구 3)은 다시 계산하지 않는다. 기본 성분값은 파이썬 추정 결과를 쓰고, `analyze_history`의 `grade_contribution`이 그 근거(이력, 적합도)를 보여 준다. 지시서 작성(도구 6)은 통지서가 대신한다.
- 조업 이력 500 heat는 `export_intranet.py`가 `company.js`의 `heats`로 내보낸다.

## 사내포털의 다른 화면

처음 접속하면 이름을 묻고, 이 과제의 직무인 제강팀 스크랩 배합 담당(AI 배합 에이전트 운영) 신입사원으로 배정한다. 입사일은 에이전트를 정식으로 쓰기 시작한 2026-09-22다. 첫날에는 인사팀 환영 메일과 사수의 인수인계 메일이 온다. 그 뒤 메일과 할 일은 그날의 배합 지시서, 검수 메모, 시세·재고를 보고 자동으로 만들어진다. 위쪽의 업무 기준일을 바꾸면 다음 날로 넘어간다.

**지난 기록·미션**(`docs/history.html`)은 평가 기간의 날짜별 조건으로 배합을 다시 풀어 보는 화면이다. 단가나 재고를 바꿔 '가정해 보기'를 할 수 있고, 검수 메모의 키워드 판정이 이상하면 담당자가 고친다. 결과를 숙련자 배합, 이전 실행과 비교한 뒤 제강팀장에게 결재를 올리면 팀장 회신 메일이 온다. 날짜별 미션(첫 결재, 위험 로트 막기, 잘못 제외된 로트 찾기, 재고 부족 대응)은 검수 메모 원문만 보고 성공 여부를 판단한다.

브라우저 계산 엔진(`docs/assets/engine.js`)은 파이썬 도구와 같은 수식을 쓴다. 5개 날짜로 대조해 보니 첫 안전여유, 숙련자 배합 원가, 같은 안전여유에서의 최적 배합 원가가 파이썬(HiGHS)과 원 단위까지 같았다. 반복 전체로 보면 모의 조업 난수가 달라서 톤당 0.1% 안팎 차이가 난다.

업무 화면(홈, AI 배합 설계, 지난 기록, 메일, 조업, 야드)에는 직원이 실제로 알 수 있는 정보만 나온다. 숨은 정답으로 채점한 결과는 'AI 배합 도입 보고서'(`report.html`)에서 도입 검증 결과로만 보여 준다. 읽음·완료 표시, 결재 기록, AI 배합 설계의 실행 기록은 각자의 브라우저(localStorage)에만 저장된다.

디자인은 `docs/assets/portal.css` 한 파일에서 관리한다. 글자 크기 단계, 카드·버튼·표·배지 규격이 모두 여기에 있고, 1440·1280·768·390px 폭에서 가로 넘침이 없는지 확인했다. 로고와 컬러 팔레트, 공식 캐릭터 리보는 브랜드 자료(`ReBorn_Steel.pdf`)를 따랐고, 이미지는 `docs/assets/`에 있다.

## 계산 방식

용강의 Cu(%)는 Σ(c_i·x_i) / Σ(y_i·x_i)로 계산한다. Cu·Sn은 정련으로 빠지지 않고, 철만 일부 손실된다고 가정했다.

성분 추정은 heat마다 `cu_pct × tap_weight = Σ c_i × charge_i`가 성립한다는 점을 이용한다. 500개 heat를 비음수 최소제곱으로 풀고, 잔차가 큰 heat(이상 로트 의심)는 빼고 다시 푼다. 편차는 '등급별 변동계수가 비슷하다'고 가정하고 잔차 분산에서 구한다.

최적화는 하루 24 heat를 한 번에 푼다. 재고를 나눠 써야 하기 때문이다. 성분 제약은 `(상한 − 안전여유) × W`다.

검증 루프의 첫 안전여유는 z × (기준 배합의 heat 성분 표준편차)다. 기준 배합은 숙련자 배합표를 쓰고, AI 배합 설계에서 등급 구성을 바꿔 배합표가 맞지 않으면 등급별 같은 비율 배합을 쓴다. 모의 조업에서 목표(기본 2%)를 넘는 강종이 있으면 모자란 만큼 여유를 키워 다시 최적화한다. 파이썬과 '지난 기록'은 최대 6회까지 반복하고, AI 배합 설계에서는 Claude가 최대 8회 안에서 반복 여부를 정한다.

## 평가 결과

LLM 없이 돌린 결과다(`python src/evaluate.py --no-llm`).

에이전트가 성분을 추정한 조업 이력은 2026-09-01~09-21(500 heat)이고, 평가는 그 뒤인 2026-09-22~10-30(39일)에만 했다. 두 기간은 겹치지 않는다. 채점에 쓴 '숨은 정답' 성분 분포는 에이전트 코드가 읽지 않는다.

표본은 하루 24 heat × 39일 = 936 heat다. 이 중 이상 로트가 있던 날이 6일(144 heat), 위험해 보이지만 실제로는 정상인 메모가 있던 날이 3일이다. 이탈률은 heat마다 숨은 정답 분포로 모의 조업을 2,000번 돌려 구한 이탈 확률의 평균이다.

| 방식 | 톤당 원가(원) | 숙련자 대비 절감(원/t) | 절감률 | 이탈률 전체 | 이상 로트 6일 | 2% 초과 heat/일 | 반복 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 숙련자 규칙 | 416,429 | 0 | 0% | 0.00% | 0.00% | 0.0 | - |
| v1 공칭성분 | 398,469 | 17,960 | 4.3% | 28.68% | 39.98% | 21.5 | 1 |
| v2 추정+검증 | 401,671 | 14,758 | 3.5% | 4.16% | 18.04% | 7.2 | 2.5 |
| v3 +검수메모 | 402,369 | 14,060 | 3.4% | 1.58% | 1.23% | 6.1 | 2.6 |

### 이탈 비용을 뺀 순절감

숙련자 배합은 이탈률이 0%지만 고급 스크랩을 넉넉히 써서 비싸다. v3는 이탈률 1.58%를 감수하는 대신 톤당 14,060원 싸다. 이탈한 heat 1톤당 손실(강등·재처리 비용)을 L이라고 하면, 순절감은 `14,060 − 0.0158 × L`(원/t)이다.

| 이탈 1톤당 손실 L (가정) | v3 순절감(원/t) | 연간 (80만 t, 가상 설정) |
|---|---:|---:|
| 5만 원 (강종 강등 손실 수준) | 약 13,270 | 약 106억 원 |
| 40만 원 (배합 원가를 전부 잃는 경우) | 약 7,730 | 약 62억 원 |
| 손익분기: 약 89만 원 | 0 | 0 |

이탈 1톤마다 배합 원가의 두 배가 넘는 약 89만 원을 잃는 게 아니라면 v3가 숙련자 배합보다 낫다. v2와 비교하면, 이탈 손실이 톤당 2.7만 원만 넘어도 v3가 유리하다. 원가는 698원/t 비싸지만 이탈률이 2.58%p 낮기 때문이다. 금액은 모두 가상 데이터로 낸 추정치다. 손실 단가 L은 이 과제에서 정해 둔 값이 없어서 범위로 보였다.

### 그 밖의 지표

성분 추정 오차(Cu, 8개 등급 평균 절대오차)는 공칭값 0.0244%p에서 이력 기반 추정 0.0198%p로 19% 줄었다. Sn은 0.00175%p에서 0.00075%p로 57% 줄었다. 등급별 Cu는 아래와 같다(단위 %).

| 등급 | 숨은 정답 | 공칭값 | 이력 기반 추정 | 추정 오차 |
|---|---:|---:|---:|---:|
| 생철A HS_A | 0.045 | 0.04 | 0.044 | −0.001 |
| 생철B HS_B | 0.070 | 0.06 | 0.101 | +0.031 |
| 중량A HMS_A | 0.170 | 0.15 | 0.163 | −0.007 |
| 중량B HMS_B | 0.250 | 0.22 | 0.273 | +0.023 |
| 경량A LS_A | 0.340 | 0.30 | 0.302 | −0.038 |
| 경량B LS_B | 0.450 | 0.40 | 0.432 | −0.018 |
| 슈레디드 SHR | 0.230 | 0.20 | 0.217 | −0.013 |
| 선반설 TRN | 0.130 | 0.12 | 0.158 | +0.028 |

공칭값은 8개 등급 모두 정답보다 낮다. 오차가 한쪽으로 치우쳐 있다는 뜻이다. 추정값은 위아래로 흩어진다. 생철B·선반설은 높게, 경량A는 낮게 나왔는데, 과거 배합에서 같이 쓰인 등급끼리 오차가 서로 상쇄된 것으로 보인다(아래 개선 과정 4번).

검수 메모 판정(키워드 규칙)은 이상 로트 6건을 모두 잡았다. 하지만 헷갈리는 메모 3건도 위험으로 보고 해당 등급을 뺐고, 그 3일은 배합 원가가 v2보다 톤당 1,773~5,869원(평균 약 3,690원) 올랐다.

하루치(24 heat) 배합을 성분 추정부터 검증까지 계산하는 데 평균 0.34초가 걸렸다(LLM 없이, 반복 평균 2.6회). LLM 에이전트 모드의 실행 시간과 사람이 배합을 짜는 시간은 재지 않았다.

### 개선 과정에서 확인한 것

1. **v1 → v2.** 공칭 성분만 믿고 상한까지 채우면 실제 성분이 공칭값보다 조금씩 높아서 이탈률이 29%까지 오른다. 이력 기반 추정과 모의 조업 루프를 넣자, 이상 로트가 없는 33일의 이탈률이 1.64%로 목표 근처까지 내려왔다.
2. **v2 → v3.** v2는 이상 로트가 들어온 6일(144 heat) 동안 이탈률이 18.0%였다. 검수 메모를 보고 위험 로트를 빼자 1.2%로 떨어졌다.
3. **안전여유 조정 규칙.** 처음에는 여유를 한 번에 크게 올렸다. 그랬더니 2회차에 이탈률이 0.5%까지 떨어지는, 지나치게 보수적인 배합이 나왔다. 모자란 만큼만 올리도록 바꿨다.
4. **이력 데이터의 다양성.** 과거 배합끼리 너무 비슷하면 회귀가 등급별 효과를 가려내지 못한다. 처음에는 선반설 Cu를 0.194로 추정했다(정답 0.13). 이력을 만들 때 배합 변동폭을 키우자 0.158로 줄었다. 그래도 생철B·선반설(높게)과 경량A(낮게)에는 오차가 남아 있다.
5. **보수적 평균 실험.** 최적화에 '추정 평균 + k × 표준오차'(k = 0, 1, 1.5, 2)를 넣어 봤다. 이탈률 차이가 노이즈 수준이라 쓰지 않았다.
6. **답이 정해진 화면에서 AI가 직접 푸는 화면으로.** 처음 만든 작업실은 날짜별로 이미 계산된 결과를 다시 보여 주는 쪽에 가까웠다. 이번에는 조건을 사람이 넣고, Claude가 도구를 골라 쓰며 풀어 가는 화면으로 바꿨다. 판단(메모 해석, 여유 결정, 재계산 여부)은 AI가, 계산은 코드가 맡는 구조는 파이썬 에이전트와 같다.

### 남은 한계

v3도 하루 24 heat 중 평균 6개 정도는 정답 기준 이탈 확률이 2%를 넘는다(평균은 1.58%). 경량A의 Cu 추정이 정답보다 낮게(0.302, 정답 0.34) 나와서, 경량A를 많이 쓴 heat가 위험해진다.

선형계획법은 분산을 모르기 때문에 한두 등급에 몰린 배합을 고르는 경향이 있다. 몰린 배합은 성분 편차가 커서 안전여유도 커진다.

키워드 규칙은 "전선 피복 발견, 전량 제거 완료" 같은 메모에도 속는다. 위 평가표는 LLM 없이 낸 결과라서, Claude로 판정했을 때의 39일 평가는 아직 없다. API 키를 넣고 `evaluate.py`를 다시 돌려야 확인할 수 있다.

AI 배합 설계 화면은 가짜 응답으로 화면 흐름(기록 분석, 풀기, 변인 분석, 통지서, 메일 통지, 발표 모드, 다시 보기, 입력 검증, 잘못된 키)을 시험했다. 실제 키로 돌린 결과와 실행당 비용은 아직 정리하지 않았다. 또 Claude가 숫자를 지어내지 않도록 도구 결과만 쓰게 했지만, 통지서 문장 속 숫자가 도구 결과와 맞는지 코드로 검사하지는 않는다. 통지서의 표는 도구 결과로 채우니, 사람이 문장과 표를 대조해야 한다.

변인 영향 분석은 한 번에 변인 하나만 바꾼다. 단가와 재고가 같이 움직이는 경우처럼 변인끼리의 상호작용은 보지 않는다. 또 안전여유를 그대로 두고 다시 풀기 때문에, Cu 함량 변화의 원가 영향은 여유를 다시 맞췄을 때보다 작게 나올 수 있다.
