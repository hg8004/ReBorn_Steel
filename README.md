# 리본스틸(ReBorn Steel) 스크랩 배합 AI 에이전트

인공지능재료공학 수업 과제. 가상의 전기로 제강사 "리본스틸"에서, 철스크랩 8개 등급의 장입량을
**원가는 최소로, Cu·Sn 규격은 지키도록** 정해 주는 AI 에이전트입니다.

> 회사, 설비, 시세, 성분, 조업 이력은 모두 AI가 생성한 가상 데이터입니다. 실제 기업·공개 데이터와 관계없습니다.

## 실행 방법

```powershell
pip install -r requirements.txt

# 1) 합성 데이터 생성 (시드 고정, 몇 초)
python src/generate_data.py

# 2) 에이전트 실행: 하루치(24 heat) 배합 지시서
python src/agent.py --date 2026-09-25

# 3) baseline, v1, v2, v3 비교 평가 + 그래프 + 홈페이지 데이터
python src/evaluate.py

# 4) 사내포털: docs/index.html을 브라우저로 열기 (start docs\index.html)
#    evaluate.py가 사내포털 데이터(docs/data/)를 같이 갱신합니다.
#    회사 데이터만 다시 만들 때: python src/export_intranet.py
```

Windows 터미널에서 한글이 깨지면 먼저 `$env:PYTHONIOENCODING='utf-8'`를 실행합니다.

### Claude API 키

LLM이 쓰이는 곳은 오케스트레이터, 검수 메모 분석(도구 2), 지시서 근거 작성(도구 6) 세 군데입니다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."     # 코드나 파일에 키를 적지 않는다
```

- 키가 있으면 `agent.py`는 Claude(`claude-opus-5-5`)가 도구를 골라 쓰는 에이전트 루프로 동작합니다.
- 키가 없으면 같은 도구를 정해진 순서로 부르는 `pipeline.run_full`로 대신 동작합니다.
  이때 검수 메모는 키워드 규칙으로, 근거 문장은 고정 템플릿으로 처리합니다.
- `python src/evaluate.py --no-llm`으로 키가 있어도 LLM 없이 평가할 수 있습니다.
- LLM 응답은 `outputs/cache/`에 저장해 다시 씁니다. 재실행 결과가 같고 비용도 아낄 수 있습니다.
- 안전 분류기가 요청을 거절하면 서버가 자동으로 다른 모델로 넘기도록 server-side fallback을 켜 두었습니다 (`src/llm.py`).

### 사내포털

- 처음 접속하면 이름을 묻고, 이 과제의 직무인 **제강팀 스크랩 배합 담당(AI 배합 에이전트 운영) 신입사원**으로 배정합니다.
  입사일은 에이전트 정식 적용일(2026-09-22)이고, 첫날에는 인사팀 환영 메일과 사수의 인수인계 메일이 옵니다.
- 메일과 할 일은 업무 기준일의 배합 지시서, 검수 메모, 시세·재고에서 자동으로 만듭니다.
  예: 지시서 초안 검토·결재 상신, 위험 로트 메모 원문 확인, 재고 부족 등급 사용량 확인, 실행 기록 점검.
- **배합 에이전트 작업실**(`docs/agent.html`): 에이전트를 브라우저에서 직접 실행합니다.
  1. 오늘 조건(단가·재고)을 보고, 값을 바꿔 '가정해 보기'를 할 수 있습니다.
  2. 검수 메모의 키워드 판정을 확인하고 담당자가 판정을 고칩니다.
  3. 실행하면 원가 최소 배합(선형계획법) → 모의 조업 1,000회 → 안전여유 조정 반복 과정을 단계별로 보여 줍니다.
  4. 숙련자 배합과 비교하고, 실행 기록끼리 비교한 뒤 제강팀장에게 결재를 올립니다. 결재 내용에 따라 팀장 회신 메일이 옵니다.
  5. 날짜별 미션(첫 결재, 위험 로트 막기, 잘못 제외된 로트 찾기, 재고 부족 대응)은 검수 메모 원문만으로 판정합니다.
- 브라우저 계산 엔진 `docs/assets/engine.js`는 파이썬 도구와 같은 수식입니다.
  5개 날짜로 대조한 결과, 첫 안전여유·숙련자 배합 원가·같은 안전여유에서의 최적 배합 원가가 파이썬(HiGHS)과 원 단위까지 같았습니다.
  반복 전체는 모의 조업 난수가 달라 톤당 0.1% 안팎 차이가 납니다. 성분 추정값은 `export_intranet.py`가 파이썬 결과를 내보낸 것을 씁니다.
- **리보 AI (timelyGPT)**: 작업실에서 '결과 요약 복사'를 누르면 지금 배합 결과가 리보 AI용 설명문으로 복사되고,
  timelyai.io의 리본스틸 스페이스(`https://timelyai.io/reborn-steel`) 채팅에 붙여 넣어 질문합니다. 키가 필요 없습니다.
  - timelyai.io는 외부 연동용 챗봇 API가 꺼져 있어(2026-11 확인) 사이트에 직접 붙이지 않았습니다.
  - TimelyChat SDK(`ai.timelygpt.co.kr`)용 키가 따로 있으면 작업실에서 화면 안 채팅으로도 띄울 수 있습니다
    (`portal.js`의 `TIMELY` 설정). 키는 코드에 넣지 않고 로그인 토큰(24시간)만 브라우저 창에 보관합니다.
  - timelyGPT는 결과 설명용 어시스턴트로만 쓰고, 에이전트의 판단(메모 판정 등)에는 쓰지 않습니다.
- 브랜드(로고, 컬러 팔레트, 공식 캐릭터 '리보')는 `ReBorn_Steel.pdf` 브랜드 자료를 따릅니다.
  이미지는 `docs/assets/`(프로필 사진 `rebo-face.png`, 로고·리보 모습 `brand/`)에 있습니다.
- 업무 화면(홈, 작업실, 메일, 조업, 야드)은 직원이 실제로 알 수 있는 정보만 쓰고, 숨은 정답(정답 기준 이탈률, 이상 로트 날짜)은 쓰지 않습니다.
  숨은 정답 채점 결과는 'AI 배합 도입 보고서'(`report.html`)에만, 도입 검증 결과로 보여 줍니다.
- 읽음·완료 표시는 각자 브라우저(localStorage)에만 저장됩니다.

`ground_truth.json`은 `generate_data.py`와 `evaluate.py`만 읽습니다. 에이전트 쪽 코드(`tools/`, `pipeline.py`, `agent.py`)는 읽지 않습니다.

## 계산 방식 요약

- 용강 Cu(%) = Σ(c_i·x_i) / Σ(y_i·x_i). Cu·Sn은 정련으로 빠지지 않고 철만 일부 손실된다고 가정합니다.
- 성분 추정: heat마다 `cu_pct × tap_weight = Σ c_i × charge_i`. 500개 heat에 대해 비음수 최소제곱으로 풀고,
  잔차가 큰 heat(이상 로트 의심)를 빼고 다시 풉니다. 편차는 "등급별 변동계수가 비슷하다"는 가정으로 잔차 분산에서 구합니다.
- 최적화: 하루 24 heat를 한 번에 풉니다 (재고를 나눠 쓰므로). 성분 제약은 `(상한 − 안전여유) × W`입니다.
- 검증 루프: 첫 안전여유 = z × (추정 편차로 계산한 heat 성분 표준편차). 시뮬레이션에서 2%를 넘는 강종이 있으면
  부족분만큼 여유를 키워 다시 최적화합니다 (최대 6회).

## 평가 결과 (LLM 없이 실행: `python src/evaluate.py --no-llm`)

**데이터 분리.** 에이전트가 성분을 추정한 조업 이력은 2026-09-01 ~ 09-21(500 heat)이고,
평가는 그 뒤 2026-09-22 ~ 10-30(39일)에만 했습니다. 두 기간은 겹치지 않습니다.
채점에 쓴 '숨은 정답' 성분 분포는 에이전트 코드가 읽지 않습니다.

**표본.** 하루 생산 계획 24 heat × 39일 = 936 heat. 이 중 이상 로트가 있던 날은 6일(144 heat),
위험해 보이지만 실제로는 정상인 메모(헷갈리는 메모)가 있던 날은 3일입니다.
이탈률은 heat마다 숨은 정답 분포로 모의 조업 2,000회를 돌린 이탈 확률의 평균입니다.

| 방식 | 톤당 원가(원) | 숙련자 대비 절감(원/t) | 절감률 | 이탈률 전체 | 이상 로트 6일 | 2% 초과 heat/일 | 반복 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 숙련자 규칙 | 416,429 | 0 | 0% | 0.00% | 0.00% | 0.0 | - |
| v1 공칭성분 | 398,469 | 17,960 | 4.3% | 28.68% | 39.98% | 21.5 | 1 |
| v2 추정+검증 | 401,671 | 14,758 | 3.5% | 4.16% | 18.04% | 7.2 | 2.5 |
| v3 +검수메모 | 402,369 | 14,060 | 3.4% | 1.58% | 1.23% | 6.1 | 2.6 |

### 이탈 비용을 뺀 순절감

숙련자 배합은 이탈률 0%지만 비쌉니다(고급 스크랩을 넉넉히 씀). v3는 이탈률 1.58%를 받아들이는 대신 톤당 14,060원이 쌉니다.
이탈 heat 1톤당 손실(강등·재처리 비용)을 L이라 하면 순절감은 `14,060 − 0.0158 × L`(원/t)입니다.

| 이탈 1톤당 손실 L (가정) | v3 순절감(원/t) | 연간 (80만 t, 가상 설정) |
|---|---:|---:|
| 5만 원 (강종 강등 손실 수준으로 가정) | 약 13,270 | 약 106억 원 |
| 40만 원 (배합 원가 전부를 잃는다고 가정) | 약 7,730 | 약 62억 원 |
| **손익분기: 약 89만 원** | 0 | 0 |

- 이탈 1톤마다 배합 원가의 두 배 이상(약 89만 원)을 잃는 경우가 아니면 v3가 숙련자 배합보다 유리합니다.
- v2와 비교하면, 이탈 손실이 톤당 약 2.7만 원만 넘어도 v3가 v2보다 유리합니다(원가는 698원/t 비싸지만 이탈률이 2.58%p 낮음).
- 금액은 모두 **가상 데이터 기준 추정치**입니다. 손실 단가 L은 이 과제에서 정한 값이 없어서 범위로 보였습니다.

### 그 밖의 지표

- **성분 추정 오차** (Cu, 8개 등급 평균 절대오차): 공칭값 0.0244%p → 이력 기반 추정 0.0198%p (19% 감소).
  Sn은 0.00175%p → 0.00075%p (57% 감소). 등급별 Cu는 아래 표와 같습니다 (단위 %).

  | 등급 | 숨은 정답 | 공칭값 | 이력 기반 추정 | 추정 오차 |
  |---|---:|---:|---:|---:|
  | 생철A HS_A | 0.045 | 0.04 | 0.044 | −0.001 |
  | 생철B HS_B | 0.070 | 0.06 | 0.101 | **+0.031** |
  | 중량A HMS_A | 0.170 | 0.15 | 0.163 | −0.007 |
  | 중량B HMS_B | 0.250 | 0.22 | 0.273 | +0.023 |
  | 경량A LS_A | 0.340 | 0.30 | 0.302 | **−0.038** |
  | 경량B LS_B | 0.450 | 0.40 | 0.432 | −0.018 |
  | 슈레디드 SHR | 0.230 | 0.20 | 0.217 | −0.013 |
  | 선반설 TRN | 0.130 | 0.12 | 0.158 | **+0.028** |

  공칭값은 8개 등급 모두 정답보다 낮습니다(한쪽으로 치우친 오차). 추정값은 위아래로 흩어집니다.
  생철B·선반설은 높게, 경량A는 낮게 나왔는데, 과거 배합에서 함께 쓰인 등급끼리 오차가 서로 상쇄되는 모양입니다(아래 '개선 과정' 4번).
- **검수 메모 판정** (키워드 규칙): 이상 로트 6건 모두 잡음. 헷갈리는 메모 3건도 위험으로 잘못 판정해 그 등급을 뺐고,
  그 3일의 배합 원가가 v2보다 톤당 1,773 ~ 5,869원(평균 약 3,690원) 올랐습니다.
- **배합 설계 시간**: 하루치(24 heat) 배합을 성분 추정부터 검증까지 계산하는 데 평균 0.34초(LLM 없이, 반복 평균 2.6회).
  LLM 에이전트 모드의 실행 시간과 사람이 배합을 짜는 시간은 측정하지 않았습니다.

### 개선 과정에서 확인한 것

1. **v1 → v2**: 공칭 성분만 믿고 상한까지 채우면 실제 성분이 공칭값보다 조금씩 높아 이탈률이 29%까지 오릅니다.
   이력 기반 추정과 시뮬레이션 루프를 넣자 평상시 이탈률이 목표 근처로 내려왔습니다 (이상 로트가 없는 33일: 1.64%).
2. **v2 → v3**: v2는 이상 로트가 들어온 6일(144 heat) 동안 이탈률이 18.0%였습니다. 검수 메모로 위험 로트를 빼자 1.2%가 됐습니다.
3. **안전여유 조정 규칙**: 처음에는 한 번에 크게 올려서 2회차에 0.5%까지 떨어지는 과잉 보수 배합이 나왔습니다.
   부족분만큼만 올리도록 바꿨습니다.
4. **이력 데이터의 다양성**: 과거 배합이 서로 너무 비슷하면 회귀가 등급별 효과를 구분하지 못합니다
   (처음에는 선반설 Cu를 0.194로 추정, 정답 0.13). 이력 생성 시 배합 변동폭을 키우자 선반설 추정이 0.158로 줄었습니다.
   그래도 생철B·선반설(높게)과 경량A(낮게)에 오차가 남아 있습니다.
5. **보수적 평균 실험**: 최적화에 '추정 평균 + k × 표준오차'(k = 0, 1, 1.5, 2)를 써 봤지만 이탈률 차이가 노이즈 수준이라 쓰지 않았습니다.

### 남은 한계

- v3도 하루 24 heat 중 평균 약 6개는 정답 기준 이탈 확률이 2%를 넘습니다 (평균은 1.58%).
  경량A의 Cu 추정이 정답보다 낮게(0.302 vs 0.34) 나와서, 경량A를 많이 쓴 heat가 위험해집니다.
- 선형계획법은 분산을 모르기 때문에 한두 등급에 몰린 배합을 고릅니다. 몰린 배합은 성분 편차가 커서 안전여유도 커집니다.
- 키워드 규칙은 "전선 피복 발견, 전량 제거 완료" 같은 메모에도 속습니다. LLM 판정 결과는 API 키로 `evaluate.py`를 다시 돌려야 확인됩니다.
