# 리본스틸(ReBorn Steel) 스크랩 배합 AI 에이전트

인공지능재료공학 수업 과제로 만든 프로젝트다. 가상의 전기로 제강사 '리본스틸'에서 철스크랩 8개 등급을 몇 톤씩 넣을지 정한다. 목표는 두 가지다. 원가는 낮추고, Cu·Sn 규격은 지킨다.

> 회사, 설비, 시세, 성분, 조업 이력은 전부 AI가 만든 가상 데이터다. 실제 기업이나 공개 데이터와는 관계없다.

사이트: https://hg8004.github.io/ReBorn_Steel/

## 실행 방법

```powershell
pip install -r requirements.txt

# 1) 합성 데이터 만들기 (시드 고정, 몇 초 걸림)
python src/generate_data.py

# 2) 에이전트로 하루치(24 heat) 배합 지시서 만들기
python src/agent.py --date 2026-09-25

# 3) 숙련자 배합과 v1·v2·v3 비교 평가 (그래프와 사내포털 데이터도 같이 갱신)
python src/evaluate.py

# 4) 사내포털 열기
start docs\index.html
```

윈도우 터미널에서 한글이 깨지면 먼저 `$env:PYTHONIOENCODING='utf-8'`를 입력한다. 사내포털용 회사 데이터만 다시 만들 때는 `python src/export_intranet.py`를 쓴다.

### Claude API 키

LLM은 세 군데에 쓴다. 도구를 고르는 오케스트레이터, 검수 메모 판정(도구 2), 지시서 근거 문장(도구 6)이다. 키는 코드에 적지 않고 환경변수로만 넣는다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
```

키가 있으면 `agent.py`에서 Claude(`claude-opus-5-5`)가 도구를 직접 골라 쓴다. 키가 없으면 같은 도구를 정해진 순서로 부르는 `pipeline.run_full`이 대신 돈다. 이때 검수 메모는 키워드 규칙으로, 근거 문장은 고정 템플릿으로 처리한다.

키가 있어도 `python src/evaluate.py --no-llm`으로 LLM 없이 평가할 수 있다. LLM 응답은 `outputs/cache/`에 저장해 다시 쓰기 때문에, 다시 돌려도 결과가 같고 비용도 거의 들지 않는다. 안전 분류기가 요청을 거절하면 서버가 다른 모델로 넘기도록 server-side fallback도 켜 두었다(`src/llm.py`).

## 사내포털

처음 접속하면 이름을 묻고, 이 과제의 직무인 제강팀 스크랩 배합 담당(AI 배합 에이전트 운영) 신입사원으로 배정한다. 입사일은 에이전트를 정식으로 쓰기 시작한 2026-09-22다. 첫날에는 인사팀 환영 메일과 사수의 인수인계 메일이 온다. 그 뒤 메일과 할 일은 그날의 배합 지시서, 검수 메모, 시세·재고를 보고 자동으로 만들어진다.

핵심은 AI 배합 설계(`docs/agent.html`)다. 정해진 답이 없는 화면이다. 스크랩 등급(추가·삭제 가능)별 단가·재고·실수율·부피밀도·Cu/Sn 평균과 편차, 강종별 Cu/Sn 상한과 heat 수, 목표 이탈 확률, 검수 메모를 넣는다. 기본값은 평가 기간의 아무 날짜에서 불러와 고칠 수 있다. 'AI 에이전트로 풀기'를 누르면 Claude(`claude-opus-5-5`)가 브라우저에서 바로 호출된다. Claude는 도구 3개(`get_conditions`, `optimize_blend`, `simulate_blend`)를 골라 쓰면서 메모를 판정하고, 안전여유를 정하고, 모의 조업 결과를 보고 다시 계산할지 판단한다. 계산은 모두 `engine.js`가 하고, Claude는 도구 결과의 숫자만 쓴다. 화면에는 Claude의 생각 요약, 도구 호출과 입력값, 결과가 순서대로 쌓인다. 끝난 실행은 브라우저에 최근 5건 저장되고, '발표 모드'로 한 단계씩(←/→ 키) 다시 보여 줄 수 있다. 토큰 사용량과 대략의 비용도 보인다.

API 키는 각자 넣는다. 키는 브라우저에서 Anthropic으로 바로 가고(`dangerouslyAllowBrowser`), 코드와 저장소에는 넣지 않는다. '기억'을 켜면 그 창(sessionStorage)에만 둔다. 키가 없으면 'AI 없이 계산'으로 같은 도구를 키워드 규칙과 정해진 여유 조정 규칙으로 돌린다. 이 둘을 같은 조건에서 돌려 보면 AI가 무엇을 다르게 판단했는지 비교할 수 있다. 9/29처럼 '선별 후 전량 제거 완료' 메모가 있는 날이 좋은 예다. 키워드 규칙은 '전선'만 보고 그 등급을 뺀다.

평가 기간의 날짜별 기록과 미션은 '지난 기록·미션'(`docs/history.html`)으로 옮겼다. 오늘 조건을 보고, 단가나 재고를 바꿔 '가정해 보기'도 할 수 있다. 검수 메모의 키워드 판정이 이상하면 담당자가 고친다. 실행하면 원가 최소 배합 → 모의 조업 1,000회 → 안전여유 조정이 반복되는 과정을 단계별로 보여 준다. 결과를 숙련자 배합, 이전 실행과 비교한 뒤 제강팀장에게 결재를 올리면 팀장 회신 메일이 온다. 날짜별 미션(첫 결재, 위험 로트 막기, 잘못 제외된 로트 찾기, 재고 부족 대응)은 검수 메모 원문만 보고 성공 여부를 판단한다.

브라우저 계산 엔진(`docs/assets/engine.js`)은 파이썬 도구와 같은 수식을 쓴다. 5개 날짜로 대조해 보니 첫 안전여유, 숙련자 배합 원가, 같은 안전여유에서의 최적 배합 원가가 파이썬(HiGHS)과 원 단위까지 같았다. 반복 전체로 보면 모의 조업 난수가 달라서 톤당 0.1% 안팎 차이가 난다. 성분 추정값은 `export_intranet.py`가 파이썬 결과를 내보낸 것을 그대로 쓴다.

리보 AI(timelyGPT)는 결과를 설명해 주는 채팅 상대로만 쓴다. 지난 기록·미션 화면에서 '결과 요약 복사'를 누르고, timelyai.io의 리본스틸 스페이스(`https://timelyai.io/reborn-steel`) 채팅에 붙여 넣어 질문하면 된다. 키는 필요 없다. timelyai.io는 외부 연동용 챗봇 API가 꺼져 있어서(2026-11 확인) 사이트에 직접 붙이지 않았다. TimelyChat SDK(`ai.timelygpt.co.kr`)용 키가 따로 있으면 그 화면 안에 채팅을 띄울 수도 있다(`portal.js`의 `TIMELY` 설정). 이 경우에도 키는 코드에 넣지 않고 로그인 토큰(24시간)만 브라우저 창에 보관한다. 메모 판정 같은 에이전트의 판단에는 timelyGPT를 쓰지 않는다.

업무 화면(홈, AI 배합 설계, 지난 기록, 메일, 조업, 야드)에는 직원이 실제로 알 수 있는 정보만 나온다. 숨은 정답으로 채점한 결과는 'AI 배합 도입 보고서'(`report.html`)에서 도입 검증 결과로만 보여 준다. 읽음·완료 표시와 결재 기록은 각자의 브라우저(localStorage)에만 저장된다.

디자인은 `docs/assets/portal.css` 한 파일에서 관리한다. 글자 크기 단계, 카드·버튼·표·배지 규격이 모두 여기에 있다. 로고와 컬러 팔레트, 공식 캐릭터 리보는 브랜드 자료(`ReBorn_Steel.pdf`)를 따랐고, 이미지는 `docs/assets/`에 있다.

## 계산 방식

용강의 Cu(%)는 Σ(c_i·x_i) / Σ(y_i·x_i)로 계산한다. Cu·Sn은 정련으로 빠지지 않고, 철만 일부 손실된다고 가정했다.

성분 추정은 heat마다 `cu_pct × tap_weight = Σ c_i × charge_i`가 성립한다는 점을 이용한다. 500개 heat를 비음수 최소제곱으로 풀고, 잔차가 큰 heat(이상 로트 의심)는 빼고 다시 푼다. 편차는 '등급별 변동계수가 비슷하다'고 가정하고 잔차 분산에서 구한다.

최적화는 하루 24 heat를 한 번에 푼다. 재고를 나눠 써야 하기 때문이다. 성분 제약은 `(상한 − 안전여유) × W`다.

검증 루프의 첫 안전여유는 z × (추정 편차로 계산한 heat 성분 표준편차)다. 모의 조업에서 2%를 넘는 강종이 있으면 모자란 만큼 여유를 키워 다시 최적화한다. 최대 6회까지 반복한다.

## 평가 결과

LLM 없이 돌린 결과다(`python src/evaluate.py --no-llm`).

에이전트가 성분을 추정한 조업 이력은 2026-09-01~09-21(500 heat)이고, 평가는 그 뒤인 2026-09-22~10-30(39일)에만 했다. 두 기간은 겹치지 않는다. 채점에 쓴 '숨은 정답' 성분 분포는 에이전트 코드가 읽지 않는다.

표본은 하루 24 heat × 39일 = 936 heat다. 이 중 이상 로트가 있던 날이 6일(144 heat), 위험해 보이지만 실제로는 정상인 메모가 있던 날이 3일이다. 이탈률은 heat마다 숨은 정답 분포로 모의 조업을 2,000번 돌려 구한 이탈 확률의 평균이다.

| 방식 | 톤당 원가(원) | 숙련자 대비 절감(원/t) | 절감률 | 이탈률 전체 | 이상 로트 6일 | 2% 초과 heat/일 | 반복 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 숙련자 규칙 | 416,429 | 0 | 0% | 0.00% | 0.00% | 0.0 | - |
| v1 공칭성분 | 398,469 | 17,960 | 4.3% | 28.68% | 39.98% | 21.5 | 1 |
| v2 추정+검증 | 401,671 | 14,758 | 3.5% | 4.16% | 18.04% | 7.2 | 2.5 |
| v3 +검수메모 | 402,369 | 14,060 | 3.4% | 1.58% | 1.23% | 6.1 | 2.6 |

### 이탈 비용을 뺀 순절감

숙련자 배합은 이탈률이 0%지만 고급 스크랩을 넉넉히 써서 비싸다. v3는 이탈률 1.58%를 감수하는 대신 톤당 14,060원 싸다. 이탈한 heat 1톤당 손실(강등·재처리 비용)을 L이라고 하면, 순절감은 `14,060 − 0.0158 × L`(원/t)이다.

| 이탈 1톤당 손실 L (가정) | v3 순절감(원/t) | 연간 (80만 t, 가상 설정) |
|---|---:|---:|
| 5만 원 (강종 강등 손실 수준) | 약 13,270 | 약 106억 원 |
| 40만 원 (배합 원가를 전부 잃는 경우) | 약 7,730 | 약 62억 원 |
| 손익분기: 약 89만 원 | 0 | 0 |

이탈 1톤마다 배합 원가의 두 배가 넘는 약 89만 원을 잃는 게 아니라면 v3가 숙련자 배합보다 낫다. v2와 비교하면, 이탈 손실이 톤당 2.7만 원만 넘어도 v3가 유리하다. 원가는 698원/t 비싸지만 이탈률이 2.58%p 낮기 때문이다. 금액은 모두 가상 데이터로 낸 추정치다. 손실 단가 L은 이 과제에서 정해 둔 값이 없어서 범위로 보였다.

### 그 밖의 지표

성분 추정 오차(Cu, 8개 등급 평균 절대오차)는 공칭값 0.0244%p에서 이력 기반 추정 0.0198%p로 19% 줄었다. Sn은 0.00175%p에서 0.00075%p로 57% 줄었다. 등급별 Cu는 아래와 같다(단위 %).

| 등급 | 숨은 정답 | 공칭값 | 이력 기반 추정 | 추정 오차 |
|---|---:|---:|---:|---:|
| 생철A HS_A | 0.045 | 0.04 | 0.044 | −0.001 |
| 생철B HS_B | 0.070 | 0.06 | 0.101 | +0.031 |
| 중량A HMS_A | 0.170 | 0.15 | 0.163 | −0.007 |
| 중량B HMS_B | 0.250 | 0.22 | 0.273 | +0.023 |
| 경량A LS_A | 0.340 | 0.30 | 0.302 | −0.038 |
| 경량B LS_B | 0.450 | 0.40 | 0.432 | −0.018 |
| 슈레디드 SHR | 0.230 | 0.20 | 0.217 | −0.013 |
| 선반설 TRN | 0.130 | 0.12 | 0.158 | +0.028 |

공칭값은 8개 등급 모두 정답보다 낮다. 오차가 한쪽으로 치우쳐 있다는 뜻이다. 추정값은 위아래로 흩어진다. 생철B·선반설은 높게, 경량A는 낮게 나왔는데, 과거 배합에서 같이 쓰인 등급끼리 오차가 서로 상쇄된 것으로 보인다(아래 개선 과정 4번).

검수 메모 판정(키워드 규칙)은 이상 로트 6건을 모두 잡았다. 하지만 헷갈리는 메모 3건도 위험으로 보고 해당 등급을 뺐고, 그 3일은 배합 원가가 v2보다 톤당 1,773~5,869원(평균 약 3,690원) 올랐다.

하루치(24 heat) 배합을 성분 추정부터 검증까지 계산하는 데 평균 0.34초가 걸렸다(LLM 없이, 반복 평균 2.6회). LLM 에이전트 모드의 실행 시간과 사람이 배합을 짜는 시간은 재지 않았다.

### 개선 과정에서 확인한 것

1. **v1 → v2.** 공칭 성분만 믿고 상한까지 채우면 실제 성분이 공칭값보다 조금씩 높아서 이탈률이 29%까지 오른다. 이력 기반 추정과 모의 조업 루프를 넣자, 이상 로트가 없는 33일의 이탈률이 1.64%로 목표 근처까지 내려왔다.
2. **v2 → v3.** v2는 이상 로트가 들어온 6일(144 heat) 동안 이탈률이 18.0%였다. 검수 메모를 보고 위험 로트를 빼자 1.2%로 떨어졌다.
3. **안전여유 조정 규칙.** 처음에는 여유를 한 번에 크게 올렸다. 그랬더니 2회차에 이탈률이 0.5%까지 떨어지는, 지나치게 보수적인 배합이 나왔다. 모자란 만큼만 올리도록 바꿨다.
4. **이력 데이터의 다양성.** 과거 배합끼리 너무 비슷하면 회귀가 등급별 효과를 가려내지 못한다. 처음에는 선반설 Cu를 0.194로 추정했다(정답 0.13). 이력을 만들 때 배합 변동폭을 키우자 0.158로 줄었다. 그래도 생철B·선반설(높게)과 경량A(낮게)에는 오차가 남아 있다.
5. **보수적 평균 실험.** 최적화에 '추정 평균 + k × 표준오차'(k = 0, 1, 1.5, 2)를 넣어 봤다. 이탈률 차이가 노이즈 수준이라 쓰지 않았다.

### 남은 한계

v3도 하루 24 heat 중 평균 6개 정도는 정답 기준 이탈 확률이 2%를 넘는다(평균은 1.58%). 경량A의 Cu 추정이 정답보다 낮게(0.302, 정답 0.34) 나와서, 경량A를 많이 쓴 heat가 위험해진다.

선형계획법은 분산을 모르기 때문에 한두 등급에 몰린 배합을 고르는 경향이 있다. 몰린 배합은 성분 편차가 커서 안전여유도 커진다.

키워드 규칙은 "전선 피복 발견, 전량 제거 완료" 같은 메모에도 속는다. LLM으로 판정했을 때의 결과는 API 키를 넣고 `evaluate.py`를 다시 돌려야 확인할 수 있다.
